# Python 语言从入门到精通 · 分板块

## README · 导览

### README_1 这套知识库解决什么

这是一套以"实际能力链路"为主轴的语言精进手册。多数入门材料按语法点排队：变量、列表、函数、类……学完仍写不出一个能交付的东西。本册换了编排轴心——按"一段代码被写出来、被读懂对象模型、被抽象、被并发调度、被测试、被观测、被调优、被交付"的真实链路推进。

地基阶段建立最小可运行单元；内核阶段拆开名称绑定、可变性、容器布局与异常语义；抽象阶段进入函数、闭包、装饰器、生成器与数据建模；工程阶段落到包结构、依赖锁定、标准库与质量门禁；精进阶段处理并发模型、解释器机理、系统边界与生产收口。知识点只是骨架，能复现、能记录、能验收才是血肉。

Python 尤其容易被"看起来很简单"误导：语法读得顺，不代表理解了对象引用、可变默认值、GIL 与导入副作用。因此自板块1 起，每个板块固定配齐三样可执行的东西：照着做就能出结果的操作清单、一套对应该场景的笔记记录方法、一组能当场判定成败的验证动作。读完不算学会，验证通过才算过关。

这套手册的"从入门到精通"不是宣传语：README_8 给出入门、进阶、精通三级刻度与晋级判据，0_1 说明七阶段与三级刻度的对应关系，板块1 用一条起步流程把"空目录 → 第一个文件 → 文件夹安排 → 打包发布"跑成实物。

起步目录的安排见 1_1 的目录决策表，发布产物清单见仓库根 `README.md`；`scripts/bootstrap.sh` 会在目标目录生成 `目录安排.md` 与 `dist/发布清单.md` 作为起步样例。

### README_3 记号、图示与笔记约定

「1」全文序号统一用「1」「2」或"第1步"，不使用带圈序号，也不使用带括号的圆圈编号。
「2」所有图示均为 ASCII 字符画，放在 `text` 代码块内。语雀与 Typora 直接渲染，无外链、无防盗链、无需解码，离线也能看。
「3」板块0 为总纲四节；自板块1 起，每个板块固定六节：X_1 核心机理、X_2 可落地操作清单、X_3 场景笔记法、X_4 案例小故事、X_5 实用验证、X_6 常见误区与进阶钩子。
「4」笔记统一采用"场景卡"结构，六字段如下：

| 字段 | 记什么 | 反例 |
| --- | --- | --- |
| 场景 | 当时在做什么、输入是什么 | 只写"研究了列表" |
| 预期 | 动手前写下的可判定结果 | 事后补写"本来就该这样" |
| 动作 | 实际敲下的命令或改动的几行 | 只写"调整了一下" |
| 观察 | 原始输出、报错原文、耗时数值 | 写成"报错了，后来好了" |
| 判定 | 通过 / 不通过 / 待查，附依据 | 空着 |
| 迁移 | 下次哪个场景能复用这条结论 | 空着 |

「5」验证统一三段式：命令 → 预期 → 判定。判定必须能被机器或数值确认，不写"感觉快了"。

```text
  场景发生 -> 写下预期 -> 执行动作 -> 记录原始观察
      ^                                    |
      |                                    v
  迁移复用 <- 归档场景卡 <- 给出判定 <- 对照预期
```

### README_4 三十分钟起步

第1步：确认解释器与隔离环境，执行 `python --version` 与 `python -m pip --version`，把两行输出原样贴进第一张场景卡的"观察"字段。
第2步：建一个空目录，创建虚拟环境并激活，写一个只打印一行文本的 `main.py`，跑通 `python main.py`。
第3步：为它补一个最小测试，执行 `python -m pytest -q`，看到通过提示后再翻到板块0。

这三步不是热身，而是后面全部板块的验证底座：任何阶段出问题，都先回到这个最小可运行单元，确认是知识问题还是环境问题。

三条检索纪律：

「1」第1步先按症状定位到机理小节，不要直接跳到命令块抄命令；命令脱离了判定口径就只剩形式。
「2」第2步遇到"环境看起来没变却行为变了"的现象，先回到 0_3 基线表与 0_4 取用口径，再怀疑业务代码；解释器分支与信任基础的变化不会出现在版本库差异里。
「3」第3步每次反查结束都要落一张场景卡，把"我以为的原因"与"实际验证出的原因"并排写进"观察"字段；反例清单比索引本身更值钱。

### README_7 配套实战项目与逐项跑通映射

前六节回答"读什么、怎么查、概念在哪"，这一节回答"整套知识库能不能真的跑起来"。本仓库以 `src/`、`tests/`、`scripts/` 与门禁脚本组成可运行工程：目录按板块拆，机理落进真实文件，再用一条门禁脚本把 12_5 的九项判分表串成可重跑的命令。它不是示例片段，换台机器照着重跑，应当得到同样的判定。

| 阶段 | 对应板块 | 实战工程里的落点 | 一条验证命令 | 对应判分项 |
| --- | --- | --- | --- | --- |
| 能跑 | 板块1 | `pyproject.toml`、`scripts/baseline.sh` | `python -m venv` 后打印 `sys.prefix` 与 `sys.base_prefix` | 隔离环境 |
| 懂对象 | 板块2、板块3 | `src/records/core.py` | `python -m pytest -q tests/test_core.py` | 测试与随机顺序 |
| 会抽象 | 板块4、板块5 | `src/records/boundary.py` | `python -m pytest -q tests/test_boundary.py` | 测试与随机顺序 |
| 会组织 | 板块6 | `requirements.lock`、`pyproject.toml` | `python -m pip check` 与按锁文件安装 | 锁定安装与依赖冲突 |
| 能并发且可验收 | 板块8、板块9 | `src/records/workers.py` | `python -m pytest -q --durations=5` | 测试与随机顺序 |
| 能精进 | 板块10 | `scripts/check.sh` 的 L3 | `python -m pytest --cov=records --cov-report=term-missing -q` | 覆盖率薄弱行 |
| 收口 | 板块11、板块12 | `scripts/rebuild_clean.sh`、`scripts/check.sh` | `bash scripts/rebuild_clean.sh` | 全项一票否决 |

三条实测校准，来自把工程真正跑通时踩到的坑：

「1」第1步按包方式启动。`python 脚本.py` 在包布局里会让相对导入失效，硬门槛表已改为 `python -m 包名.模块`；干净重建时还要用已安装形态再验一次，不能只靠 `PYTHONPATH` 碰巧可导入。

「2」第2步类型检查必须有命令。9_5 的命令块必须同时含测试、覆盖率与 `python -m mypy 包目录` 三条，只写"类型检查报告无新增错误"而不给命令，等于没有门禁。

「3」第3步环境差异不改判定口径。实测遇到两类适配，处理办法都只改"怎么把命令跑起来"，不碰通过标准。

部分环境未提供 ensurepip，`python -m venv` 会直接失败。做法是备好环境创建工具，或改用带系统站点包的隔离方式；真正不复用宿主站点包的重建另用独立环境创建工具完成。覆盖率数据文件若落在对 sqlite 写不友好的卷上，会报 disk I/O error。

做法是把覆盖率数据与类型检查缓存换到临时目录，而不是跳过覆盖率这一项。

两条的判定仍看"前缀不同、按锁文件重建、同命令重跑结果一致"，12_5 已补这条边界声明。

命令与通过标准见 12_5 的九项判分表。判分表是对照模板，不是标准答案：每次换环境都要自己重跑、自己填"现场判定"列；把别人的"通过"抄进自己的清单，等于把 12_5 的一票否决架空。

### README_8 从入门到精通：三级能力刻度与晋级判据

前七节给的是"怎么查、怎么跑、怎么落地"，这一节回答"我现在算到哪一级、凭什么进下一级"。七阶段是能力链路，三级是能力刻度，两者是同一条路的两把尺子，不是两套课程。

| 层级 | 对应板块 | 能力定义 | 晋级判据 | 典型卡点 |
| --- | --- | --- | --- | --- |
| 入门 | 板块1 至板块5 | 能从空目录建起第一个文件、跑通最小可运行单元、解释名称绑定与拷贝、写出可替换的小组件与对象模型 | 换台机器照清单重建全绿，且能说清每个文件夹解决什么 | 脚本能跑，却说不清用的是哪个解释器 |
| 进阶 | 板块6 至板块9 | 能按 `src` 布局组织包与依赖、处理并发与异步、让测试与类型检查替自己把关 | 干净环境按锁文件重建成功；随机顺序、覆盖率、类型检查三类门禁全绿 | 本地能导入，打包后子包消失 |
| 精通 | 板块10 至板块12 | 能用剖析数值定位瓶颈、解释解释器机理、守住系统边界与信任链、按清单交付并回滚 | 12_5 九项全通过；回滚演练有本地实物证据；接手的人只凭索引能定位判断依据 | 代码没动却行为变了，找不到判断依据 |

板块0 是总纲，不计入三级，但每一级都允许随时回查。

三条晋级纪律：

「1」第1步晋级不看读了多少页，只看"上一级的产出物能不能成为下一级的输入"。阶段三写出的可替换组件，到阶段四要能被换成真实实现；换不动就说明上一级没过关。

「2」第2步每级留一张晋级判定卡（12_3 第十二类），六字段照专用模板填；"判定"列只写"通过"或"不通过"，不写"大致掌握""感觉会了"。

「3」第3步允许横向回查。到了精通阶段遇到对象模型或导入问题，按 README_5 反查回入门机理，不因为"已经学过"就跳过复跑。

起步那一关单独按一条线验：空目录 → 第一个文件 → 文件夹安排 → 第一次跑通 → 打包发布。实战工程的 `scripts/bootstrap.sh` 把这条线做成可重跑的命令，输出 `BOOTSTRAP_PASSED` 才算入门起步流程通过。

目录安排的决策依据见 1_1，最小发布动作见 1_2，整体交付物见仓库根 `README.md` 与 12_5 判分表；起步样例的 `发布清单.md` 由 `scripts/bootstrap.sh` 生成。
