## 板块0 · 总纲：学习路径与边界

### 0_1 学习路径

路径按"能力阶段"划分，不按日历划分。每阶段只有一个硬门槛：该阶段的通关验证必须跑通。

| 阶段 | 对应板块 | 主线任务 | 产出物 | 通关验证 |
| --- | --- | --- | --- | --- |
| 阶段一 · 能跑 | 板块1至板块2 | 解释器、虚拟环境、包管理、基础语法、异常 | 一个可直接运行且测试通过的命令行小程序 | 环境复现一致，测试全绿 |
| 阶段二 · 懂对象 | 板块3 | 名称绑定、可变性、容器布局、拷贝、引用计数 | 一张自己画的对象引用草图 + 一段无别名 bug 的数据处理代码 | 身份与相等性断言全绿 |
| 阶段三 · 会抽象 | 板块4至板块5 | 闭包、装饰器、生成器、协议、类型注解、面向对象与数据建模 | 一个可替换实现的小组件（内存版与文件版） | 换实现不改调用方，类型检查与测试全绿 |
| 阶段四 · 会组织 | 板块6至板块7 | 导入机制、包结构、依赖锁定、标准库实战、日志与指标 | 一个可按安装形态重建的包与构建产物 | 干净环境重建成功，导入链无循环 |
| 阶段五 · 能并发且可验收 | 板块8至板块9 | GIL 边界、线程、进程、协程、任务取消、测试与类型检查、覆盖率门禁 | 一个可超时、可取消、可优雅退出的管道与全绿门禁记录 | 压测下无任务泄漏、无竞态，门禁全绿 |
| 阶段六 · 能精进 | 板块10至板块11 | 复杂度、剖析、解释器机理、GC 观测、系统边界与降级 | 一份前后对比的性能基线表 | 指标改善有数值且可复现 |
| 阶段七 · 收口 | 板块12 | 反模式清单、评审检查单、交付演练 | 一份自己的通关记录 | 12_5 总验收全项通过 |

阶段与板块严格按编号区间划分，板块1至板块12 全部有归属，无遗漏。阶段之间的过渡不是"学完就翻页"，而是"上一个产出物成为下一个的输入"：阶段三写出的可替换组件，在阶段四的工程化环节会被换成真实存储实现；阶段六的剖析数据来自阶段四那个服务，而不是凭空造的玩具函数。

```text
  能跑 -> 懂对象 -> 会抽象 -> 会组织 -> 能并发 -> 能精进 -> 收口
    |        |         |         |         |         |        |
  最小单元  引用草图  可替换件  可重建包  可取消管道  基线表  通关记录
```

### 0_2 使用建议与边界声明

「1」本册聚焦 Python 语言本身的对象模型、标准库用法与工程实践；不覆盖特定业务领域的算法推导与领域建模，遇到领域问题应以该领域的权威资料为准。
「2」示例以标准解释器与标准库可直接复现为准；涉及第三方组件时只描述接口契约与验证方式，不假定特定版本的行为永远不变。
「3」命令、输出与判定标准以你自己机器上实际跑出的结果为准。不同解释器版本在提示文案、默认参数与类型语法上存在差异，遇到不一致时以本地 `help()` 与官方文档入口为准，而不是照抄本册的示例输出。
「4」学习节奏用相对阶段表达，不设定具体年份、季度或日期，也不承诺某个时点必须达到某个水平；进度只看验证通过率。
「5」笔记法不是附加装饰。每个板块的 X_3 都给出该场景专用的记录模板，若跳过记录，X_5 的验证就失去了可追溯的对照基准。
「6」边界之外的内容（如特定框架源码、特定云厂商部署细节）应以官方文档为准；本册提供的是可迁移的判断框架与验证方法。
「7」解释器支持状态、安装器、证书信任包与基础镜像属于高频变动信息，本册只给判断框架与验证动作，不写死任何版本号或日期；遇到安全公告、终止支持或行为变更，以官方渠道的当前说明为准，并把核对结果记进场景卡。

### 0_3 环境基线自检

在动笔写任何业务代码前，先把基线固定下来，后续所有"环境背锅"的争论都能用这张表一秒裁决。

| 检查项 | 命令 | 通过标准 |
| --- | --- | --- |
| 解释器可用 | `python --version` | 输出版本标识，无 command not found |
| 隔离环境生效 | `python -c "import sys; print(sys.prefix)"` | 路径指向虚拟环境目录而非系统目录 |
| 包管理器可用 | `python -m pip --version` | 输出版本标识且归属当前解释器 |
| 依赖清单可导出 | `python -m pip freeze` | 输出可解析的包与版本行 |
| 工具链与信任链自更新 | `python -m pip check`、`python -m pip --version` | 无依赖冲突；按官方当前说明核对支持状态与证书信任包，不沿用旧缓存 |
| 格式化与检查可用 | 在环境中执行一次格式检查命令 | 退出码为 0 或明确列出待修文件 |
| 测试可用 | `python -m pytest -q` | 能收集到至少一个用例并通过 |

把表中各项结果原样粘贴进场景卡的"观察"字段，判定写"基线通过"。这张卡在整个学习周期里只需建一次，但每次换机器、换容器镜像都要重跑一遍。

表中 `pytest` 及后续命令里出现的覆盖率插件、构建工具均需单独安装，不在标准库内；本册只描述其用途与验证口径，不假定预装。若选择标准库自带的 `unittest`，把测试命令换成 `python -m unittest discover -v`，验证口径保持不变。

另有一条容易漏的口径：所有存量虚拟环境都要单独走一遍本表，不能只验当前激活的那一个；解释器分支若已终止支持，应记为迁移待办而非继续加固。

### 0_4 外部资料与社区的取用口径

起步最常见的弯路，是同时打开十几个教程，却连一个最小可运行单元都没跑通。资料按用途分层，每层只留一个主入口、一个备用入口；下列代表入口是检索起点，不是背书，也不构成版本依据。

| 用途层 | 代表入口 | 取用方式 | 记进场景卡的内容 |
| --- | --- | --- | --- |
| 权威口径 | Python 官方教程（中文）、官方文档 | 行为有差异时第一顺位查证 | 查了哪一条、本地输出是否一致 |
| 官方动态 | Python 官方论坛（discuss.python.org） | 查发布、安全与支持状态一类公告，只取判断框架不抄版本号 | 核对动作与本地输出 |
| 零配置试跑 | 支持在线运行代码的教程页：廖雪峰的官方网站、W3Schools、菜鸟教程实例 | 只用来建立手感，不替代本机验证 | 在线结果与本机执行结果的差异 |
| 系统入门 | 菜鸟教程、廖雪峰的官方网站、W3Schools | 选一套主线读完基础，其余只查单点 | 进度用验证通过率记，不用页数记 |
| 进阶实战 | Real Python | 按爬虫、数据分析、Web 开发等方向选一个做完整小项目 | 项目验收项与未覆盖点 |
| 练习与自检 | 牛客网 | 每个知识点配一道能判分的题，兼顾校招题型 | 错题归入反例清单 |
| 问答排障 | Stack Overflow、官方论坛 | 先搜再问，提问附最小可复现片段 | 问题要点、采纳结论、本地复跑结果 |
| 社区交流 | Reddit 的 r/Python 与 r/learnpython、Python中文开发者社区、编程论坛（Bcwhy） | 找资源推荐、项目灵感与职业建议，顺带读英文原始表述 | 可迁移结论与本地复跑结果 |
| 开源阅读 | GitHub | 读开源项目代码、议题与变更 | 可复用写法与取舍理由 |

```text
  官方口径 -> 在线试跑 -> 系统教程 -> 方向实战 -> 练习自检
      |                                            |
      +------------------> 本地复跑 <---------------+
                              |
                              v
                    场景卡(观察/判定/迁移)
                              ^
                              |
              问答社区 / 中文社区 / 开源议题
               (先过滤杂项，再取结论)
```

三条取用纪律：

「1」第1步先用权威口径定结论，再用教程与练习补手感；两者冲突时以本地实际输出与官方说明为准，不照抄示例输出。
「2」第2步对社区页面做资料甄别：导航分类、官方文档入口、按主题归档的技术版块属于有效信息；推广、重复发布的无信息帖、与语言主题无关的源码交易和广告属于杂项，不进笔记、不进卡片库。
「3」第3步提问与讨论守住协作底线：不人身攻击、与人为善；先给最小可复现片段与已跑过的验证，再描述差异，对方给的结论在本地复跑一遍才归档。

版本与信任链按四个可复跑动作处理。证书信任包、安装器、基础镜像与存量虚拟环境都可能出现"业务代码没变、TLS 客户端的信任基础变了"的情况，这类信息不写死任何版本号或日期：

「1」第1步核对当前解释器是否仍在官方支持范围内；已终止支持的分支不再接收安全修复，应列为迁移待办，而不是继续在上面加固。
「2」第2步清点本机所有存量虚拟环境，逐个更新包管理器与证书相关依赖；更新走官方给出的可信通道，不复用旧缓存，也不只验当前激活的那一个环境。
「3」第3步重建容器镜像时显式拉取基础镜像并按 digest 核对，再禁用层缓存重建，确认新层里的证书集合已更新；把这一步写进交付清单，不靠"上次构建过"推断。
「4」第4步把每次核对的本地输出贴进场景卡的"观察"字段，判定只写"与官方当前公告一致"或"待迁移"，不抄公告里的版本号与日期。

对应到本册：查证动作落在 2_3 的假设—反例卡，依赖与工具链核对落在 6_3 的决策卡，信任链变更落在 11_3 的边界演练清单，最终在 12_3 统一归档。

把三类常见外部资料落成资料取用卡，可以直接照着填：

| 资料类型 | 只取什么 | 明确不取什么 | 归档到哪 |
| --- | --- | --- | --- |
| 安全公告类 | 四个可复跑动作：核对解释器支持状态、清点所有存量虚拟环境、禁用层缓存重建镜像、干净环境复跑门禁 | 公告里的具体版本号、日期、外链安装命令 | 11_3 边界演练清单 |
| 社区发言规范类 | 提问纪律：先给最小可复现片段与已跑过的验证，再描述差异 | 情绪化争论、人身攻击、无证据的结论 | 0_4 资料取用卡 |
| 社区聚合页类 | 节点导航、官方文档入口、按主题归档的技术版块 | 推广、重复发布的无信息帖、与语言主题无关的源码交易与广告 | 12_3 资料取用卡 |

判定只写"与官方当前说明一致"或"待迁移"；写不出这两句，说明还在抄结论而不是做验证。这里特别要区分两件事：解释器分支是否仍受支持，决定的是"该不该继续加固"；证书信任包与基础镜像是否更新，决定的是"TLS 客户端还能不能连上"。

两者都不会出现在版本库差异里，却都能让业务代码零改动的行为改变。配套实战工程的门禁脚本、干净重建脚本与回滚演练脚本已把这些动作固化成可重跑的命令。

#### 信任链变更的四类对象

安全公告类资料最容易抄错的，是把"某个包的版本号"当成结论。可迁移的是下面这张表：证书包、包管理器、基础镜像、存量虚拟环境各自会怎么变、各自怎么验。业务代码一行没改，TLS 客户端的前提也可能已经变了。

| 对象 | 会怎么变 | 可复跑动作 | 判定 |
| --- | --- | --- | --- |
| 证书信任包 | 根或中间证书被移除、信任列表调整 | 在干净环境复跑一次外部请求与门禁 | 与官方当前说明一致 / 待迁移 |
| 包管理器与安装器 | 自身携带的信任配置随更新变化 | 清点所有存量虚拟环境并逐一更新，不复用旧缓存 | 全部环境均已核对 |
| 基础镜像与层缓存 | 旧层里仍是旧的证书集合 | 显式拉取基础镜像并按 digest 核对，再禁用层缓存重建 | 基础镜像 digest 已更新，新层门禁复跑一致 |
| 存量虚拟环境 | 当前激活的那个正常，其余仍是旧配置 | 逐个环境打印前缀并复跑门禁 | 全部环境结果一致 |

#### 存量虚拟环境的清点动作

"清点所有存量虚拟环境并逐一更新"如果只写成一句原则，执行时最容易只更新当前激活的那一个。把它拆成四步，每一步都留可粘贴的输出。

| 步 | 动作 | 该看的输出 | 判定 |
| --- | --- | --- | --- |
| 第1步 | 枚举项目目录、用户级环境目录与容器挂载里所有带环境身份标记的位置 | 每处配置文件的路径 | 清单完整，没有"忘了还有这个环境" |
| 第2步 | 对每个环境用它的解释器分别打印环境身份与解释器路径 | 前缀与基础前缀、可执行文件位置 | 每个条目都能说出它属于哪个项目 |
| 第3步 | 对每个环境分别复跑一次导入校验与门禁，不复用旧缓存 | 导入结果、依赖冲突检查、门禁逐条结果 | 全部通过且结果一致 |
| 第4步 | 把清单、逐条输出与"已核对 / 待迁移"写进场景卡 | 一张带最后复核列的核对表 | 没有只写"环境没问题"的合并结论 |

常见误判是把"当前激活的那个正常"当成"全部正常"：旧环境往往不报错，只是仍带着过时的信任配置。第2步逐个打印身份、第3步逐个复跑，目的正是让沉默的那批环境也留下证据。解释器支持状态与证书链分开判定，前者写"待迁移"，后者写"与官方当前说明一致"，不合并。
