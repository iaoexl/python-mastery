## 板块7 · 标准库实战：路径、编码、时间、日志与子进程

### 7_1 核心机理与关键概念

板块6 把项目立起来，板块7 往里填真实能力。标准库的用法有一个共同倾向：把"自己拼字符串、自己管资源"换成"交给专门对象"。

`pathlib.Path` 用对象表达路径，`/` 运算符拼接、跨平台一致，`read_text` 与 `open` 配合上下文管理器自动收尾。`json` 处理结构化文本，注意数值精度、时间字段需自定义转换、未知字段与编码三项；大文件用逐行或流式思路，别一次读成整份字符串。

`datetime` 最容易出错的是"天真时间"与"带时区时间"混用：比较、算术、序列化都要求两边语义一致，存储统一用带时区表示。`logging` 是分层设施而非打印语句：logger 有层级，handler 决定去向，format 决定字段。

把请求标识放进日志上下文，才能让一条请求在多处日志里串起来。`subprocess` 负责外部命令，参数用列表传递、显式设超时、检查返回码，避免用字符串拼接交给 shell 解释。

```text
  外部世界             标准库边界                 内部代码
  +--------+      +-------------------+      +----------+
  | 文件   | -->  | pathlib / open    |      |          |
  | 文本   | -->  | json / csv        | ---> | 业务对象 |
  | 时钟   | -->  | datetime + tzinfo |      |          |
  | 子进程 | -->  | subprocess.run    |      |          |
  | 运行态 | <--  | logging + 上下文  | <--- |          |
  +--------+      +-------------------+      +----------+
        每一条边界都要写明: 编码 / 超时 / 错误语义
```

还有四处边界，踩中任何一处都不是"写法不优雅"，而是语义直接出错：

| 边界 | 正确做法 | 错误做法的后果 |
| --- | --- | --- |
| 金额与十进制运算 | `decimal.Decimal` 并显式设定上下文精度；从字符串或整数构造，不从 float 构造 | 用二进制浮点累加，或从 float 构造 Decimal，继承尾差 |
| 地区时区 | `zoneinfo.ZoneInfo` 搭配带时区时间 | 手算固定偏移，切换当天的时间戳集体错位 |
| 跨信任边界序列化 | 只用 `json` 等纯数据格式 | 对不可信数据用 `pickle`，反序列化即可执行任意代码 |
| 缓存大对象 | `weakref` 做不延长生命周期的引用 | 全局字典强引用，缓存对象永远不被回收 |

`zoneinfo` 解决的是"偏移不是常量"：同一地区在不同日期可能对应不同 UTC 偏移。存储用 UTC 时刻加 IANA 地区标识，或用 `ZoneInfo` 构造带时区时刻，不要用固定偏移的 `timezone(offset)`；展示时再按地区规则换算。精简容器还需核对 tzdata 是否已安装，否则 `ZoneInfo` 找不到地区规则。

`pickle` 的红线更硬，它反序列化时会按数据里的指示构造对象，只适用于自己完全控制的进程间传递，绝不用于网络输入、用户上传或跨组织的缓存文件。`weakref` 则补上板块3 引用计数那张图的另一半：想"能查到、但不因此留住"时，弱引用是唯一不干扰回收判定的方式。

**文本处理三件套：正则、结构化文本与时间**

标准库把格式解析交给专门模块，业务代码只处理解析后的结构。

正则表达式由 `re` 模块提供：`re.search` 扫描全文找第一处匹配，`re.match` 只从开头匹配，`re.findall` 返回全部匹配串，`re.sub` 完成替换，`re.compile` 把常用模式预编译以便复用。模式里频繁出现反斜杠时用原始字符串书写，避免与字符串自身的转义规则冲突。

结构化文本由 `json` 模块处理：编码用 `json.dumps`，解码用 `json.loads`，落盘与读盘分别用 `json.dump` 与 `json.load`。类型对应是固定的——字典对应对象，列表与元组对应数组，字符串对应字符串，整数与浮点对应数值，`True`、`False`、`None` 分别对应 `true`、`false`、`null`。集合与自定义对象不在默认支持范围内，需要调用方先转换。

时间处理分清"时刻"与"日历"两层：`time` 模块提供时间戳与 `strftime` 格式化，`datetime` 提供可运算的日期时间对象，`calendar` 生成日历。时间戳是与时区无关的秒数，格式化输出则依赖本地时区或显式指定的时区，两者混用会产生数小时的偏差；结论与 7_1 的时区口径一致。

### 7_3 场景笔记法：外部数据联调与契约留痕

外部数据类场景的坑多半在"边界数据"上，笔记要按输入形态分栏，而不是按函数名分栏。

| 字段 | 本场景填写要求 |
| --- | --- |
| 场景 | 写明数据来源（文件、网络、子进程）、编码、数据规模、是否流式 |
| 预期 | "畸形输入被明确报错；带时区时间可比较；子进程超时可控；日志能串联同一请求" |
| 动作 | 贴出路径拼接、编码转换、时区设置与超时参数那几行 |
| 观察 | 粘贴原始报错、返回码、日志行、耗时数值 |
| 判定 | 三类边界输入（空、超大、畸形）全部符合预期记"通过" |
| 迁移 | "凡接外部数据先写畸形输入用例；凡调外部命令先写超时用例" |

实用补充：给每个外部接口建一张"字段契约表"，记录字段类型、编码、是否可空、时间是否带时区。JSON 的"字段缺失"与"字段为 null"在业务里常常被混为一谈，这张表是区分它们的依据。

### 7_4 案例小故事：同一笔订单，两个时区算出了两个日期

某跨境对账报表每天都差几笔，差额不大却从不为零，且只在时区规则切换前后出现。业务代码没做复杂运算，只是把交易时间截成日期再分组汇总。

根因在时间表示：一处从外部拿到的时间字符串没带时区，被当成天真时间直接参与比较；另一处用固定偏移手工换算，可规则切换那几天的偏移本就变了。两边对同一笔交易算出了不同日期，汇总自然对不上。日志里没有异常，数据也"看起来都合法"。

修法三步：入口统一解析为带时区的时刻，存储保留地区标识；展示换算走 `zoneinfo.ZoneInfo`，不再手算固定偏移；金额一律用 `decimal.Decimal` 并从字符串构造，显式设定精度，避免浮点尾差再叠一层分位误差。

补的测试覆盖切换日前后各一天，断言同一笔交易在两种表示下归属同一日期，且金额合计精确相等。

复盘时把这条写进 7_3 的字段契约表，新增两列"时间是否带时区""金额用哪种数值类型"。此后遇到跨边界数据，先填这两列再写解析代码。这类错误不会抛异常，只会让报表"差一点"。

### 7_5 实用验证：命令、预期与判定

第1步：把下面这段保存为 `verify_subprocess.py`，执行 `python verify_subprocess.py`。用 `sys.executable` 启动慢子进程，避免依赖某个平台自带的 `sleep` 命令。

```python
import subprocess
import sys
from datetime import datetime, timezone
from pathlib import Path

p = Path("data") / "sample.json"
now = datetime.now(timezone.utc)
slow = [sys.executable, "-c", "import time; time.sleep(5)"]
try:
    r = subprocess.run(slow, timeout=0.2, capture_output=True)
    print("未超时，returncode =", r.returncode)
except subprocess.TimeoutExpired:
    print("超时已捕获: timeout ok")
print("路径 =", p, "带时区 =", now.tzinfo is not None)
```

第2步：在完整项目里执行下列门禁命令。

```bash
python -m pytest -q
python -m compileall -q .
```

预期：慢子进程在约 0.2 秒触发超时并打印 `超时已捕获: timeout ok`；`路径` 一行跨平台一致，`带时区 = True`；畸形 JSON 输入被明确报错而非产生半初始化对象；日志行中包含注入的请求标识；`-q` 测试全绿。

判定：四项以上全中记"通过"。补一道对照验证：把 `timeout` 去掉再跑同一慢子进程，调用应挂住约 5 秒后打印 `未超时，returncode = 0`；能看到"挂住"与"按时返回"的差别，超时才算真的验证过。

### 7_6 常见误区与进阶钩子

「1」误区：把路径当字符串手工拼接。用 `Path` 与 `/`，跨平台与尾部分隔符都省心。
「2」误区：天真时间与带时区时间混着比较或存库。统一用带时区表示，边界处显式转换。
「3」误区：用 `print` 代替日志。层级、去向、字段与采样都无从控制，排障时等于没有线索。
「4」误区：用字符串拼命令并交给 shell。改用列表参数，并始终检查返回码与超时。
「5」进阶钩子：给 `logging` 加一个自定义 Filter，把请求标识自动注入每条记录，用一条测试请求把跨模块日志串起来，把串联结果贴进场景卡。
